# Obeserva v0.6.1 — Worker Context Isolation

**Release date:** 2026-05-28  
**Install:** `composer require scout/laravel`

---

## Summary

**v0.6.1 — Worker Context Isolation** hardens Obeserva for long-running PHP workers. Queue, Horizon, Octane, and RoadRunner runtimes reset tracer and context state between jobs and requests so spans and trace metadata do not leak across worker cycles.

## Highlights

### Dedicated worker isolation

`WorkerRuntimeDetector` identifies queue and Horizon worker processes (`queue:work`, `horizon:work`, `horizon:supervisor`). After each job completes or fails, `WorkerContextResetter` flushes the tracer, clears active context, and resets database and Horizon registries.

### Octane and RoadRunner

When optional packages are present, termination listeners on Octane request/task/tick events and RoadRunner worker events perform the same reset — covering Swoole-backed Octane deployments.

### HTTP and sync queue unchanged

Sync queue jobs inside HTTP requests and PHPUnit tests are not treated as dedicated workers, so request-scoped tracing continues to work as before.

## Configuration

| Variable | Default | Description |
|----------|---------|-------------|
| `OBESERVA_WORKER_CONTEXT_ISOLATION` | `true` | Enable worker context isolation |
| `OBESERVA_WORKER_FLUSH_AFTER_JOB` | `true` | Flush tracer after each job in dedicated workers |
| `OBESERVA_OCTANE_ISOLATION` | `true` | Reset on Octane termination events |
| `OBESERVA_ROADRUNNER_ISOLATION` | `true` | Reset on RoadRunner termination events |

Config keys: `obeserva.worker.*` in `config/obeserva.php`.
